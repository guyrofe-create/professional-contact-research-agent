# Professional Contact Research Agent

כלי לאיסוף שיטתי של כתובות מייל מקצועיות ופומביות בלבד עבור אנשי מקצוע וארגונים בתחום בריאות האישה, הריון, לידה ופוריות.

## קטגוריות
המאגר כולל בין היתר רופאי נשים ופוריות, רופאי משפחה, מנהלי מרפאות,
מרכזי בריאות האישה, מרפאות קהילה, יחידות IVF, מיילדות, דולות,
יועצות הנקה, פיזיותרפיסטיות רצפת אגן ואנשי מקצוע נוספים סביב הריון ולידה.
Instagram אינו חלק ממאגר היעדים.

## קלט
CSV או XLSX עם לפחות שתי עמודות:

```csv
name,category
ישראל ישראלי,gynecologist
שרה כהן,doula
```

ניתן להוסיף עמודות אחרות. הן אינן חובה.

## התקנה והרצה

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python agent.py targets.csv --out output --resume
```

`--resume` גורם לכלי להמשיך מה-checkpoint ולא לבצע שוב יעדים שכבר הוכרעו.
שדרוגי אלגוריתם ממירים את ה-checkpoint במקום למחוק אותו: מועמדים ישנים נשמרים,
מועמדים בטוחים ממשיכים הלאה, והיתר מסומנים לבדיקה חוזרת. יעדים שנוקו מהמאגר
נשמרים ב-`output/retired_targets.jsonl` לצורכי ביקורת.
יעד שממתין לספק חיפוש נשמר עם `next_retry_at` ואינו מעכב יעדים חדשים.
הריצה בענן רשאית לעבור על כל מאגר היעדים; מגבלת הזמן של GitHub וה-checkpoint מגינים עליה, ואם הזמן מסתיים הריצה הבאה ממשיכה בדיוק מהמקום שבו נעצרה.

## פלט
* `output/audit.xlsx` - כל יעד שנבדק, כולל מי שלא נמצא עבורו מייל.
* `output/contacts.xlsx` - כתובות שעברו את מדיניות הבטיחות העדכנית, לאחר הסרת כפילויות. `outreach_scope` מבדיל בין אדם לבין כתובת ארגונית/משותפת, ו-`personalization_safe` קובע אם בטוח לפנות בשם האדם.
* `output/checkpoint.jsonl` - checkpoint לאחר כל אדם.
* `output/summary.json` - מספר היעדים הכולל, כמה נבדקו, הוכרעו, ממתינים, נמצאו ומיילים ייחודיים.

## כללי אימות
הכלי אינו מייצר או מנחש כתובות מייל. כתובת נשמרת רק אם היא הופיעה בפועל בדף ציבורי שנפתח במהלך המחקר. כתובות דוגמה, תיבות מערכת שאינן מתאימות לפנייה, מאגרי לידים צד שלישי, כתובות שירות של אינדקסים וכתובות שאינן משויכות בבירור ליעד נפסלים. נשמרים גם `source_url` של הכתובת ו-`identity_url` שמוכיח את הקשר ליעד. `confidence` הוא ציון התאמה ואינו הוכחה בפני עצמו.

## תהליך החיפוש
המנוע מעדיף מקורות ישירים: פרופילים מאינדקס הר״י, רשומות משרד הבריאות,
פרופילים מקצועיים שמורים ואתרי מוסדות. רק כשמקור ישיר אינו מספק כתובת
מתבצעת שאילתת חיפוש מדויקת. העבודה נעשית במקביל במספר קטן ומבוקר של עובדים,
והתור מתקדם בסבב בין הקטגוריות כדי שרופאי משפחה או מנהלי מרפאות לא ייתקעו
מאחורי קטגוריה גדולה אחרת. תשובת “אין תוצאות” אינה נחשבת עוד לקריסת ספק;
המפסק מופעל רק אחרי רצף של תקלות חיבור אמיתיות.

דף רשימת רופאים או דף מחלקה כללי אינו מספיק לזיהוי אדם. המנוע עובר ממנו רק לקישור פרופיל שהשם מופיע בהקשר המבני שלו. באתרים אישיים הוא רשאי לבדוק עמודי contact/about בשכבה אחת; באתרי בתי חולים, אוניברסיטאות ואינדקסים הוא אינו משוטט לעמודים כלליים. כתובות מכירות, שיווק, תמיכה, לוגיסטיקה ומחלקה בינלאומית אינן מיוחסות לאדם. כתובת משותפת של מרפאה או איגוד נשמרת פעם אחת בלבד ומסומנת כנתיב ארגוני, כך שאין שליחה כפולה ואין פנייה אישית שגויה.

כאשר מוגדר secret בשם `SERPAPI_KEY`, החיפוש משתמש ב-SerpApi. בלעדיו נעשה שימוש מוגבל ב-DDGS עם מכסת בקשות ומפסק תקלות. אין לעקוף CAPTCHA, התחברות או מגבלת גישה.

## הערה חשובה
יש להשתמש רק במידע מקצועי שפורסם לציבור ובכפוף לתנאי השימוש, robots.txt והדין החל. אין להשתמש בכלי לעקיפת login, CAPTCHA, הגנות אתר או מגבלות גישה.
